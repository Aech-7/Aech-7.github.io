Humanoid Supervisor Robot

A humanoid robot that listens, reasons with a locally hosted LLM, speaks, and performs physical actions through tool calling.

Harshada Kale & Siddhart Dangi·MakeBhavan Project Course (ME 299)·Supervisors: Dr. Aniruddh Mali, Prof. Pratik Mutha

The idea

I built this project as part of the MakeBhavan Project Course with the idea of making a humanoid robot that could act as a supervisor in a makerspace. Makerspaces have many different tools and machines, and a lot of the interaction usually depends on a person being around to guide users. Instead of building another robot that simply follows predefined commands, I wanted to experiment with giving the robot a more natural interface — talking to it.

The final system can listen for a wake word, understand a spoken query, process it using a locally running LLaMA model, generate a spoken response, and translate parts of that interaction into physical movements such as turning its head, moving its eyes, and opening and closing its jaw. The complete system runs on edge hardware without depending on a cloud API.

System architecture

The interesting part of the project was not really any one component, but getting all of them to work together. The main pipeline starts with the microphone and speech-to-text, followed by wake-word detection. Once activated, the spoken query is passed to a locally running LLaMA 3.1 8B model. The model produces structured JSON describing both the response and the physical action that should be performed.

Hardware

I used a Rubik Pi as the main computer for speech recognition, LLM inference and text-to-speech, while an Arduino Mega handles the low-level servo control. The robot uses two 35 kg torque servos for the jaw and head rotation and an SG90 servo for lateral eye movement. A PCA9685 PWM driver controls the servos through I2C, while the Arduino communicates with the Rubik Pi over USB serial. The servos run from a separate external supply with a common ground.

Connecting the LLM to the robot

One of the parts I found most interesting was making the LLM interact with the physical robot. Instead of asking the model to directly generate motor commands, I constrained it to return structured JSON containing an action, response and arguments. I then created a decorator-based command registry where Python functions such as moving the head, moving the eyes, or opening the jaw become tools available to the LLM.

This gives a useful separation between reasoning and hardware control. The LLM decides what the robot should do, while the corresponding Python function is responsible for actually executing the action. Because of this, adding a new physical capability only requires adding another command function rather than changing the whole system.

Software pipeline

For wake-word detection, I chose not to train a dedicated wake-word model. Instead, the incoming speech is converted to text and encoded using all-MiniLM-L6-v2 embeddings. I compare the resulting embedding with the embedding of "hey robot" using cosine similarity. This also allows variations such as "hey there robot" or "hello robot" to activate the system.

I also had to make sure that speech recognition, LLM inference and text-to-speech did not block one another. The application therefore uses separate threads for the different stages of the pipeline, while the serial layer handles motor commands with reconnection and input clamping. This became especially important once the robot had to listen, reason, speak and move as part of the same interaction.

Making the robot move

The physical mechanisms were kept relatively simple, but I wanted the movements to make the interaction feel more natural. The eyes can move laterally, the head can rotate between left, center and right positions, and the jaw is synchronized with speech. These mechanisms are driven by predefined servo positions, while the higher-level decision of when to use them comes from the command interface.

Results

The final system gives an end-to-end interaction between natural language and a physical robot. The robot can detect the wake phrase, process a spoken query using the local LLM, generate a spoken response and perform physical actions selected through the tool-calling interface. The jaw can synchronize with speech, while head and eye movements can be triggered through natural-language commands.

What I would improve

The biggest limitation at the moment is latency. The complete response currently takes around 7–8 seconds, with most of the delay coming from local LLM inference. The robot also has predefined physical actions, limited dialogue capabilities and no visual perception yet. The next version would add a camera for face detection and user tracking, more expressive body movements, more natural TTS and continuous multi-turn interaction. I would also like to experiment with smaller local models to reduce inference time.
