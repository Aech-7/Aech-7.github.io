01 — The problem

The goal of this project is to make a robot roll dough to a more uniform thickness without relying only on a fixed position trajectory. This is harder than it first appears because dough is deformable and its surface is not perfectly flat. As the roller moves across the dough, the contact conditions can change continuously.

A fixed Cartesian trajectory therefore does not provide enough information about what is actually happening at the contact. The robot needs to sense its interaction with the dough and use that information while executing the rolling motion.

02 — Hardware

The system is built around a Franka robot arm equipped with a rolling tool and force/torque sensing. A RealSense camera provides visual information about the dough surface. ROS2 is used to connect the robot, sensing and control components into a single system.

04 — Force-aware control

The main control idea is to separate the motion that defines the rolling pass from the interaction force that determines how the roller behaves against the dough. The robot moves along the rolling direction while the force signal provides feedback about whether the roller is actually in contact and how strongly it is interacting with the material.

The force signal is filtered before being used by the controller, and the system keeps track of the rolling position and contact state. This makes it possible to distinguish the actual rolling region from approach and retreat motions and to analyse the force experienced during each pass.

05 — Contact detection

Contact state is useful because not every part of the robot trajectory represents rolling. During approach and retreat, the roller should not be treated as being in contact with the dough. During the rolling region, however, the measured force becomes part of the control and analysis pipeline.

06 — Surface estimation

Force alone does not describe the final shape of the dough, so the vision system is being used to obtain information about the dough surface. The surface can be represented as a height map along the rolling direction, providing a way to compare the thickness across the dough rather than evaluating a pass only from the force signal.

07 — Virtual wall

Another part of the control architecture is a virtual wall / potential-field constraint. Instead of simply imposing a hard position limit, the idea is to create a soft constraint that generates a corrective command as the roller approaches an estimated surface boundary.

This allows the force-control and position-limiting behaviors to work together. The surface estimate can be shared between the pass-execution loop and the real-time wall logic, keeping the safety constraint separate from the main rolling trajectory.

08 — Rolling pass

09 — Current status

The current work is focused on making the basic sensing-and-control pipeline reliable on the physical robot. The system has the robot-side rolling setup, ROS2 infrastructure, force/torque sensing, contact-state handling and the structure for using camera-based surface information in the controller.

The next stage is to make the surface estimation accurate enough for closed-loop use and then use the resulting measurements to evaluate how the dough thickness changes from pass to pass.

10 — What I learned

Working on this project has made the difference between position control and physical interaction much clearer to me. A position trajectory can tell the robot where to move, but it does not directly tell it what is happening at the contact. For a deformable material like dough, that interaction becomes an important part of the control problem.

It has also made me think more carefully about how sensing and control should be separated. Rather than making the controller responsible for every part of the system, the surface estimator, pass-execution logic and virtual-wall layer can each have a clear role. This structure should make it easier to experiment with different control strategies as the project develops.
