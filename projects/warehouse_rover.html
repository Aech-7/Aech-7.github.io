Autonomous Warehouse Rover

Building the SLAM and localization system for an autonomous warehouse robot designed to navigate storage aisles and automate rack-level inventory scanning.

ROS2 SLAM Localization Autonomous Navigation
01 — The project

The goal of Eternal was to build an autonomous warehouse rover capable of navigating storage aisles and scanning racks to automate inventory tracking. The complete system combines mobile navigation, a vertically moving camera, QR-code detection and inventory logging.

My main contribution was the SLAM and localization pipeline. This provided the rover with an estimate of its position and a representation of the surrounding warehouse environment, allowing the higher-level navigation system to plan and execute movement through the mapped space.

02 — SLAM pipeline

For mapping, I worked with ROS2 and SLAM Toolbox, using a 2D RPLIDAR as the primary source of environmental information. The lidar continuously provides range measurements around the robot, which are used to build a 2D occupancy-grid representation of the warehouse while simultaneously estimating the robot's pose.

The rover also provides IMU and wheel-odometry measurements. These different sources of information were combined through an Extended Kalman Filter (EKF) to obtain a more stable estimate of the robot's state.

03 — Mapping in simulation

Before relying on the physical rover, we tested the mapping pipeline in a simulated warehouse environment. A CAD-based warehouse model was imported into Gazebo, allowing us to evaluate the lidar data and SLAM behavior in a controlled environment.

Once a usable map was generated, it could be saved and reused by the navigation system. This created the link between the perception layer and autonomous navigation: SLAM builds the representation of the environment and provides the robot pose that the navigation stack can use.

04 — Localization

A map by itself is not enough for autonomous navigation. The robot also needs to know where it currently is within that map. This made localization an important part of the system rather than treating SLAM as simply a mapping algorithm.

The pose estimate produced by the localization pipeline was used by the navigation stack to move between predefined checkpoints. We tested path planning, checkpoint arrival, obstacle avoidance and recovery behavior while evaluating how localization errors affected the resulting motion.

05 — Physical rover

The physical rover uses a differential-drive base with independent wheel control. The sensing setup includes a RPLIDAR, IMU and wheel odometry, while the Raspberry Pi acts as the main computing platform. The resulting localization system connects the sensor hardware to the ROS2 navigation stack running on the robot.

Sensor and computing hardware used for localization.

06 — Navigation

Once the map and localization pipeline were working, the generated pose information could be used by Nav2 for autonomous navigation. The rover was tested on predefined routes and checkpoints, with the navigation stack handling path planning and obstacle avoidance.

Autonomous navigation using the generated map and localization system.

07 — Results

Repeated motion tests showed horizontal positioning within approximately ±10 cm. The navigation system was able to use the generated map and localization estimates to move between predefined checkpoints while handling obstacles and recovery behavior.

The SLAM system ultimately became the layer connecting the physical sensors to the autonomous navigation stack. Once the rover knew where it was and had a representation of its surroundings, the rest of the warehouse workflow could be built on top of that localization system.

08 — What I learned

Working on the SLAM portion of this project gave me a much better understanding of what is involved in taking a mobile robot from receiving lidar measurements to actually estimating where it is in an environment. I had to think about sensor data, coordinate frames, odometry, map quality and how localization errors propagate into the navigation system.

The most useful part for me was seeing SLAM as part of a larger robotic system rather than as an isolated algorithm. The map and pose estimate I worked on ultimately had to be useful to Nav2 and to the physical robot, which made the connection between perception, localization and motion much clearer.
